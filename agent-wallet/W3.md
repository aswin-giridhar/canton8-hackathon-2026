# W3 measurement harness

This harness runs the attack matrix and contention measurement against a real
Canton ledger through JSON Ledger API v2. The normal target is `daml sandbox`.

## Run

Terminal 1, from the repository root:

```bash
export PATH="$HOME/.daml/bin:$PATH"
cd agent-mandate
daml build
daml sandbox --port 6865 --json-api-port 7575 \
  --dar .daml/dist/agent-mandate-0.0.1.dar
```

Terminal 2:

```bash
cd agent-wallet
python3 test_auth.py
python3 w3_harness.py --concurrency-runs 100 --latency-charges 100
```

Outputs:

- `W3-RESULTS.md`: one-page scorecard and compact attack matrix.
- `w3-results.json`: raw evidence, including verbatim ledger error bodies and
  every individual concurrency/latency observation.

Use smaller counts for a quick smoke test:

```bash
python3 w3_harness.py -n 3 --latency-charges 3 --skip-daml-tests
```

## Correctness guards

- A rejected attack passes only if its expected ledger reason is present. A
  broken wallet that rejects everything does not pass.
- Every contention run passes only with exactly one successful charge and one
  aborted charge against the same mandate contract id. Both submissions charge
  `1.0` against an initial cap of `1.0`, so two successes would prove overspend.
- After each race, the harness reads active contracts back from the ledger and
  verifies exactly one new successor, `spent == 1.0`, and consumption of the
  original mandate. Stable party hints mean contracts accumulate between runs,
  so verification uses a before/after contract-id set difference, not a count.
- HTTP 500s and other infrastructure failures are reported separately and are
  never counted as contention aborts.
- Sequential latency counts only complete ledger transactions which returned a
  successor `Mandate` contract.
- The Markdown report is derived from the raw JSON evidence.

## DevNet auth

`ledger.py` enables refresh-aware bearer authentication when `C8_IDP`,
`C8_CLIENT_ID`, and `C8_CLIENT_SECRET` are set. It refreshes 60 seconds before
expiry and invalidates/retries once on HTTP 401. `TokenSource` is locked so a
concurrent run performs one refresh rather than one refresh per worker.

The current custom `Mandate` DAR is not deployed to DevNet, so do not label a
local W3 report as a DevNet measurement. Running against DevNet additionally
requires package deployment, hosted parties with `CanActAs`, and funding if the
charge is wired to a token-standard holding.
